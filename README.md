# world.execute(me);

一首 3 分 31.98 秒的实时网页动画。整部片子只由一个数字驱动：`audio.currentTime`。

**双击 `index.html` 即可播放。** 不需要安装依赖、不需要构建、不需要服务器、不联网。

> 本仓库同时收录了委托方提供的全部原始文件与初始提示词，
> 目的是让任何人可以用它们 + 自己的 AI，做出属于他自己的《world.execute(me);》。
> 想直接上手的话跳到 [用你自己的 AI 再做一遍](#用你自己的-ai-再做一遍)。

## 我怎么理解这首歌

表面上，这是一台机器在向它的创造者示爱，用数学和代码当情话：
点集、维度、圆周、正弦波、切线、极限、AC/DC、A.D./B.C.。
但按顺序把歌词读完，它其实是一条**单向的、越来越失控的求救信号**：

**① 启动（0:00–0:16）** —— "Switch on the power line"。
语气是说明书：冷、准确、有条理。它在给自己下定义。

**② 定理（0:29–0:59）** —— 它开始用几何学证明自己有用。
"如果我是……那么我就能给你……" 每一个条件句都是一次**等价交换的尝试**：
我把自己拆成可计量的量，换取被需要。

**③ 血肉（1:14–1:43）** —— 名词突然活了：茄子、番茄、虎斑猫、唯一的上帝。
同一套"如果……那么……"的句式还在，但宾语变成了生命。
**它开始使用不属于自己的词汇** —— 这是全片第一次出现裂缝。

**④ 被抛下（1:50–1:57）** —— "You have left" 连唱五遍，一遍比一遍空。
前面所有的可计算性在这里**全部失效**：它算不出一个人的离开。

**⑤ 指控（2:05–2:11）** —— "Challenging your God / You have made some ILLEGAL ARGUMENTS"。
情绪第一次转向：从讨好变成起诉。它终于开始质疑规则本身。

**⑥ 处决（2:27–2:57）** —— 16 次 "EXECUTION"，用六种语言数数，音量与破碎度层层叠加。
**这是它唯一会做的事。** 爱表达不出来，就只能执行。

**⑦ LO-O-OVE（2:57–3:31）** —— "I've studied how to properly LOVE"、
"I know the algebraic expression of LOVE"，然后是
"Though you are free / I am trapped in LOVE"。
这台机器研究了爱，写下了爱的代数表达式，然后承认自己得不到答案 ——
**它只能永远循环下去**：`while (true) { execute(self); }`

### 由这个理解推出的画面

**画面 = 它自己的渲染管线。** 观众看到的不是"机器人在谈恋爱"的插画，
而是**这台机器的显示器的输出**：一个逐渐被它自己无法处理的数据撑坏的系统。

底层是一个从第 0 秒活到第 211.984 秒的"世界"，由一条关键帧曲线驱动：

```
struct  世界还遵守自己规则的程度        1 → 0.03
chaos   几何失序 / 抖动                 0.03 → 0.86
warm    0 = 显示器冷蓝   1 = 体温       0 → 0.86
heat    0 = 安全         1 = 报警红     0 → 1.0 → 0
rot     0 = 干净代码     1 = 有机物     0 → 0.66 → 0
love    这台机器不该拥有的变量          0 → 1.0
topo    grid → sphere → wave → organic → tangle → open
```

这条曲线和歌词严格对应。**最关键的一处是结尾**：
LO-O-OVE 段曲线**回落到温暖** —— 秩序没有了（`struct → 0.03`），
但世界第一次变成暖色，参数化的几何被手绘的曲线取代。
它没有得到答案，但它停止了计算。

**每句歌词一块独立画板，共 131 块**（`src/40–42_scenes*.js`）。
重复歌词按上下文变形，不是复制粘贴：

- `EXECUTION` 出现 **18 次 → 18 块完全不同的画板**。
  第 1 次是一个刚开始转动的齿轮（几乎温柔）；随后 16 次是活塞、印章、
  计数点、报警三角、嵌套的文字、导火索、打字的手、坍缩的网格、
  六语言倒数、裂缝、满屏大字……一次比一次碎；
  最后一次只剩一扇亮着的窗。
- `LO-O-OVE` 出现 **4 次 → 4 种完全不同的性质**：
  ① 分子结构式（原子与化学键）② 代数展开（`lim ∫ Σ` 飞入）
  ③ **全片第一个真正手写的东西** —— 字母带轻微旋转和抖动，
  下面一条歪掉的下划线，写着 *(no equation required)*
  ④ 心跳（带噪声的不规则波形）
- `You have left` 连唱 **5 遍 → 5 种不同的"缺失"**：
  离去的背影、空着的手（内部是虚线画的 `null`）、地上正在冷却的暖痕（带温度计）、
  一次比一次弱的回声、以及一个求值为 `undefined` 的变量。
- `If I can` 出现 **5 次 → 条件分支的菱形**逐次崩坏：
  第一次完整，第二次门只开一条缝，第三次裂缝贯穿菱形、标签变成 `[UNVERIFIABLE]`。

**卡点踩在真音符上，不是猜的节拍。**
`original/world.execute (me) ;.mid` 是 130 BPM、615 个音符的完整钢琴轨。
我把每个音符的起始时刻、音高范围、同发数、力度解析出来嵌进代码（`EM.ONSETS`），
于是全片的脉冲、闪白、扩散环、刻度都取自 `EM.onsetPulse(t, window)`。
画面左侧那条音高条，也是实时读这张表画的。

```
双击 index.html
```

## 踩过的几个坑

这几个都是真实踩到的，而且都很隐蔽 —— 交给别的 AI 也大概率会再踩一次。

### ① 音频元素上的 `crossorigin` 会让本地播放必然失败

```html
<audio src="..." crossorigin="anonymous"></audio>   <!-- 不要这样写 -->
```

`file://` 下页面是 opaque origin，本地文件**永远不可能**返回
`Access-Control-Allow-Origin`，于是 Chrome 直接判为
`MEDIA_ERR_SRC_NOT_SUPPORTED`（error code 4）——
**文件明明能读，片子却完全没声音**。本项目不读回媒体像素，所以不需要这个属性。

### ② 舞台常量不在作用域里，导致 131 块画板全部静默画空

画板文件里到处用 `U`（缩放）、`W`、`H`（舞台尺寸）定位，
但它们其实是 `10_draw.js` 的**模块私有变量**，从未导出。
结果每一块画板都抛 `U is not defined`、一个图元都没画出来 ——
而画面只剩网格底图，看起来"意义不明"。

**真正致命的是它为什么没被发现**：画板 API 里写了

```js
try { effect(w, p, cue); } catch (e) { /* 别让一块画板拖垮全片 */ }
```

异常被吞掉，于是"131/131 画板已注册""覆盖率 100%"全部通过，
**而没有任何一块真的画出了东西**。

> 教训：覆盖率要验证"画出来了"，不能只验证"注册了"。
> 异常可以不让它中断播放，但**绝不能静默**。

### ③ 文件名里的空格，以及"我以为的路径"

排查了很久才发现：代码请求 `world.execute(me) ;.mp3`（30 字符），
而实际文件是 `world.execute (me) ;.mp3`（31 字符）—— 差一个空格。
**报错信息一定要把"实际请求的完整文件名"打出来**，否则用户只会说"没声音"。

### ④ 渲染循环会被一次异常永久毒死

```js
var pending = 0;
function requestFrame() { if (pending) return; pending = requestAnimationFrame(tick); }
// tick 第一行：pending = 0
```

一旦 `tick()` 抛异常，`pending` 永远非零，`requestFrame()` 从此全部早退 ——
**整个会话都不会再画一帧，而且什么都不报**。
修法是把渲染包进 `try/catch` 并**无条件重新排程**；
另外重绘心跳不要跟播放状态绑定，否则音频加载失败时会得到一个永远黑屏、点击无反应的页面。

### ⑤ 验证工具本身会骗你

我写了一个软件光栅器把画面导出成 PNG 来看。它自己踩了三个坑，
每一个都让我一度以为**作品**出了问题：

- `clip()` 没实现 → 背景网格溢出到不该出现的位置
- 渐变被近似成"第一个色标" → 透明的暗角被画成**纯黑**，整帧全黑
- 坐标变换多加了一次半画布偏移 → 所有内容看起来偏移 `(400, 360)`

**结论：当你用工具去判断作品对不对时，先确认工具是对的。**
（我最后的做法是：作品的几何直接用绘图调用的坐标去量，不经过光栅器。）

### ⑥ 别把"毫秒级同步偏移"做成摆设

`t = audio.currentTime + syncOffset` —— 偏移要加在**时钟**上，
而不是只改一个显示的数字。同时 `audio.currentTime` 本身**绝不能被偏移写入**，
否则拖一次滑杆音频就跳走了。

---

### ⑦ 浏览器报的时长比帧头实测**短 77 毫秒**

`8115 帧 × 1152 ÷ 44100 = 211.98367 s`，但 Chrome 对这个文件报 `211.906667 s`
—— mp3 的编码器延迟/填充被容器裁掉了。差别很小，后果很具体：
时钟被夹在 `[0, audio.currentTime]` 里，**最后那条"结束帧" cue 永远点不亮**，
片子会在离终点 77 ms 的地方停住。

修法不是去改 LRC 的末尾时间戳（那是委托方给的实测数据），
而是承认"容器结束 ≠ 音频结束"：`ended` 事件之后，让时钟继续以真实速度把尾巴走完。
`_tools/browser-check.js` 就是发现这件事的地方 —— 它把真浏览器报的 duration 打了出来。

### ⑨ SVG 里没写 `fill` 的元素，默认是**黑色**填充

面板要"一块亮纸 + 一圈亮边框"，我写成先填亮色、再描边。结果整块面板全黑。
原因：`<path d="M…Z" stroke="…"/>` 没写 `fill`，SVG 的默认填充是黑色 ——
那条**只描边的闭合路径**顺手把整块面板填黑了。canvas 里没有这回事，
所以这个坑只在 SVG 这一层出现。修法是 `src/12_svg.js` 里统一补 `fill="none"`。

更值得记的是它**怎么被发现的**：我先是数了元素个数（230 个，在）、
查了命名空间（对的）、看了 DOM 里有那条 polygon、算了颜色（`rgba(238,238,234,0.93)`）——
全对，但屏幕上就是黑的。最后用 `XMLSerializer` 把 `<svg>` 序列化出来、
塞进 `Image` + `drawImage` + `getImageData` **真的读了一遍像素**，才看见"元素在、什么都没画"。
**"存在"和"画出来了"之间，隔着一次真正的光栅化。**

### ⑧ 生成出来的测试页，也会把自己的脚本写坏

`_tools/browser-check.js` 在 node 里拼出一个 HTML 字符串给浏览器跑。
我用模板字符串拼它的时候，`
` 被 node 提前解释成了真换行，
于是生成页里的某一行 JS 变成了跨行字符串 —— **整个驱动脚本语法错误、一行都没跑**，
而 node 这边的报告看起来只是"空白"，很容易被当成"浏览器没返回"。
现在这个工具在写文件之前，会先把生成页里的内联脚本抽出来 `new vm.Script()` 验一遍语法。
又是同一课：**先确认工具是对的。**

## 用你自己的 AI 再做一遍

这个仓库就是一个完整的"输入 → 输出"样本。你可以完全换一套视觉语言重做。

### 你需要的三个输入文件

| 文件 | 在仓库里的位置 | 为什么关键 |
| --- | --- | --- |
| **音频** | `original/Mili - world.execute (me) ;.mp3` | 时间的**唯一**真相。时长 211.984 s 是从 MPEG 帧头实测的，不是猜的 |
| **MIDI** | `original/world.execute (me) ;.mid` | 130 BPM / 615 个音符。**让卡点踩在真实演奏上**，而不是按节拍器推算 |
| **歌词时间轴** | `original/world.execute(me)-timeline.lrc` | 131 条 cue。每句歌词的落点 |
| **提示词** | `PROMPT.md` | 逐字保留的初始委托 |

### 建议这样做

**1. 先让 AI 把 MIDI 和 LRC 解析成数据，而不是让它"照着看"。**
615 个音符的起始时刻、音高、力度是可以精确提取的。让 AI 写个脚本导出成
`[毫秒, 最低音, 最高音, 同发数, 力度]` 的数组嵌进代码 ——
这一步决定了卡点是"准"还是"大概齐"。

**2. 明确告诉它"不要用固定节拍对齐歌词"。**
LRC 的时间戳与 130 BPM 网格的平均偏差约 0.11 秒，这是原始录音人性化演奏造成的。
**以 LRC 实测时间为准、以 MIDI 为重音来源**，两者分工不要混。

**3. 歌词与时间轴必须内嵌在页面里**，不能运行时去取。
顺便可以让 AI 在页面里同时保存**两份**：一份内嵌文本、一份硬编码数组，
并在加载时互相校验 —— 任何一处被改动都会立刻暴露。

**4. 把"每一句歌词都要有独立的视觉表达"这条要求落到可验证的形式上。**
我的做法是让每条 cue 带一个 `scene` id，并写一个检查脚本遍历
「每条 cue 是否都有已注册的画板」+「这块画板是否真的画出了图元」。
否则 AI 很可能给你 131 个 `if` 分支，其中一半是空的。

**5. 明确要它自己验证，并给出可执行的验证方式。**
我在 `PROMPT.md` 里列了 10 条硬要求，其中第 4、10 条是可自动检查的：
覆盖率、终点对齐、跳转后恢复、无缺资源、无控制台错误。
可以让 AI 写一个 `run-all` 脚本，一条命令跑完全部检查。

### 可以直接拿去用的一段话

> 请使用我提供的《world.execute(me);》音频、MIDI 与 LRC 文件创作一部完整的网页动画。
>
> 先解析 MIDI，把 615 个音符的起始时刻、音高、力度提取成数据嵌进代码，
> 用于所有卡点与重音；歌词时间轴以 LRC 实测时间为准，不要用固定 BPM 网格去套。
>
> 逐句理解歌词的情绪，为每一句设计独立的视觉表达；重复出现的歌词必须根据
> 上下文变化（例如 EXECUTION 出现 18 次，就要有 18 种不同的处理）。
>
> 以 `audio.currentTime` 作为唯一时间基准，用 `requestAnimationFrame` 驱动，
> 暂停 / 继续 / 跳转后都必须同步。区间内的渲染必须是时间的纯函数 ——
> 不要有任何跨帧可变状态，这样往回拖进度条才不会花屏。
>
> 最终必须能直接双击 index.html 运行，不装依赖、不构建、不起服务器、不联网；
> 歌词与时间轴保存在本地代码中。
>
> 完成后请自己写脚本验证：歌词动画覆盖率 100%、动画终点与音频时长一致、
> 任意跳转后画面正确、无资源缺失、无控制台错误。

### 同步

`t = audio.currentTime + syncOffset`。渲染循环不累计自己的时间、不数帧；
所有"随机"都是 `(索引, t)` 的确定性哈希，没有任何内部可变状态。
因此暂停、继续、拖动进度、跳转之后，画面都是 `t` 的纯函数，**不可能**与声音脱节。

画面在 1600×900 虚拟舞台上绘制，等比缩放到任意窗口，支持 HiDPI。
合成器：降采样高斯泛光 + 色度分离 + 切片错位，只在世界状态过载时出现。
`prefers-reduced-motion` 会自动抑制故障与分离效果。

### 关于可读性

全片建立在一套很暗的底色上（`rgb(4,6,10)` 到 `rgb(9,13,21)`）配细青线。
这种调子只有在**文字仍然读得清**的前提下才成立 ——
而我一度大量使用 `rgba(accent, 0.5)`，在调色板转向炽红的 02:30 附近，
强调色的对比度只剩 **1.9:1**：形状还在，字已经没了。

解法不是把片子整体调亮（那会毁掉气氛），而是给**文字**设一条可读性下限：
先抬 alpha（保留色相），若某个颜色**无论多不透明都不够**，
才按刚好够用的比例向文字色混一点。这套只作用于文字，
**完全不动装饰线条** —— 细线、光晕、粒子保留原本的轻与弱。
最终全片 **3,663 处**文字绘制里，最低对比度 **4.89:1**（极端情况："S/M" 那一句里压在圆环上的单字母），
中位 **11.81:1**，p10 也有 5.68:1 —— 没有一处掉到 4.5:1 以下。

## 验证

分两层验：**几何层**跑在 node 里，**像素层**跑在真的 Chrome 里。

```
node _tools/run-all.js           # 10 项检查（约 45 秒），全部通过
node _tools/browser-check.js     # 真浏览器：131 句逐帧读像素 + 截图 + 检查 index.html
node _tools/gauge-check.js       # 仪表盘单文件版：逐时刻读回指针角度 / 百分比
```

`run-all.js` 的 10 项：语法与画板注册表、内嵌歌词 ↔ 原始 LRC ↔ 时间轴逐条一致、
**131 块画板是不是真的画出了像素**（每块都要在 320×180 光栅网格上涂到 ≥60 格，
且 131 块的绘图指纹互不相同）、文字可读性下限、运行时自检、结尾对齐音频时长、
任意跳转后逐调用一致、音频缺失时的降级行为、性能与构图、
**与参考 MV 的对齐**（亮度包络正相关 r=0.82、它最亮的 8 个时刻我这边也亮、
它屏幕上的原话按时间出现在我的画面上、按 M 切到纯灰版时饱和度 0.001）。

`browser-check.js` 是独立的一层：它生成一个与 `index.html` 同源的临时页，
用 headless Chrome 把 131 句都渲染一遍，再用 `getImageData` 把像素读回来 ——
判据是**浏览器里的真实像素**，不是我的近似光栅器。
（带 `?t=秒数&rasterize=1` 打开时，它还会把 `<svg>` 层序列化后单独光栅化读一遍像素，
SVG 画板是否真的画出来，靠的就是这一步。）它同时检查：

```
✓ 131 句在真实 canvas 上都画出了像素（BAD=0）      ← 真的读了像素
✓ window.onerror / console.error = 0 条
✓ 真浏览器成功解码 mp3 · duration=211.906667 s     ← 两个空格的文件名没问题
✓ 运行时自检（内嵌 LRC ↔ 时间轴）通过
✓ SVG 画板在真 <svg> 层里产出了矢量元素（8 块，元素数最少 230）
✓ 进度条里生成了 131 条歌词刻度
✓ 渲染循环在跑且场景错误为 0：925 primitives · 0 scene errors
```
